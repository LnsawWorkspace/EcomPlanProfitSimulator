# 方案敏感性分析图（Graphs）

> 本模块是 ecomskill 的逻辑子模块之一，公共规则见根目录 `Skill.md`；报告页见 `planReport.md`。
> 站点方案报告页提供 6 个敏感性分析图按钮（4 个单变量 + 3 个双变量中的 1 个"Roi"系列 + 2 个"价格"系列），本文先详解 **ROI 曲线图**（`planReportRoiGraph.html`），其他图后续按需补充。
> 本文所有结论均来自 2026-08-20 对"拼多多推广"方案（售价 139.9/1000单/退款 8%/ROI 4/睡衣+睡裤）的真机实测 + `page/planReport/js/planReportRoiGraph.js`（788 行）源码核对。

## 0. 共同前提

- **ROI 口径（所有图通用）**：图中 ROI = **GMV ÷ 推广成本**（工具算法，非平台 ROI）——勿与电商平台 ROI 直接对比；涉及 ROI 时引导关注推广回报率（利润÷广告费）并提醒 ROI 陷阱（自然成交变推广成交）。详见 `references/qa.md`。
- **依赖广告投放**：报告页的 ROI 类图表按钮（ROI / 售价+单量 / ROI+售价 / ROI+单量）只有方案设置了广告（`planParams.advertising.name` 非空）才会打开；否则 toast「该方案未设置广告投放，无法查看 XX 图表」。脚本要先确认 `plan_params_ops raw <方案>` 的 `advertising.name`。
- **URL 三参数**：所有分析图页都是 `?workspaceId=&groupId=&planId=` 强依赖。
- **计算量控制**：双变量图慢（1万点位约 30~40s，见报告页 SKILL.md）；单变量相对快，但**步数仍受页面限制**（ROI 1~10 步长 0.1 = 91 点很顺；扫描范围过大时单图可能也慢）。读脚本里 `roi-graph-end - roi-graph-start / step` 即估算点数。
- **dataZoom 滑条（所有分析图都有）**：除了改参数范围，每张图上还有 **ECharts 的 dataZoom 组件**（图底部/右侧可拖动的区间缩放滑条）——拖动它可以直接放大看局部区间，不用重新计算。脚本通过 `option.dataZoom` 输出当前缩放范围（如 `{type:'slider', start:0, end:100}`）。
  **主动缩放**：脚本支持 `--zoom-start 0 --zoom-end 40`（百分比 0-100）——先缩放再截图，用于放大看局部；**双变量图点位非常密集，光靠调参数范围可能不够，配合 dataZoom 放大是标准做法**（只影响显示/截图，不改底层数据）。
- **图例（legend）交互（单变量折线图）**：图上方有图例，可点切换**显示/隐藏曲线**——等价于"人类选中要看的曲线"。**页面默认只显示「利润 + 利润增长率」两条**（其余初始隐藏），AI 读图默认拿全量 series；截图/聚焦时用 `--show-series "利润,资本回报率"` 只显示指定曲线。
  **⚠ 量程压制**：多图例同时显示时，**大量程曲线会把小量程曲线压成一条直线**——y 轴刻度由大数值曲线（利润/广告费，几万）主导，小数值曲线（利润率 0.2、增长率 0.01、回报率）就被压扁到贴底/贴顶的直线，看不出形状。**所以聚焦看某条小量程曲线时，务必用 `--show-series "利润率"` 只看它**，避免被其他图例影响（读数据不受影响——series 全量照读，只是显示/截图聚焦）。
- **页面不开自动重新生成**：页面打开后用方案当前的"售价/单量"预填输入框，但 ROI 范围（开始/步长/结束）固定默认 1/0.1/10；改范围后要点"重新生成分析图"才会重算。

### 1.3 真实行为 / 怎么算

**操作规则**：页面上的「开始 / 步进 / 结束」三个输入框**都是 ROI 的值**；「售价」「单量」输入框默认预填方案当前值，**也可以临时改——只影响本次图，不落库、不改方案参数**（页面是独立沙盒，可快速对比不同售价/单量下的 ROI 曲线，改完关掉页面即恢复）。

- **ROI 步进精度可到 0.0001**，但精度越高 → 扫描点数越多 → 算力消耗越高。**必须缩小区间范围来降低计算次数**：`计算次数 = (结束 − 开始) / 步进 + 1`。
- 例：1~10、步进 0.1 → 91 点（快）；1~2、步进 0.0001 → 10,001 点（慢）。**建议控制在 1 万以内**，脚本会估算并警示。
- 调整后**必须点「重新生成分析图」按钮**（#roi-graph-generate-btn）才会重算。

**粗扫 + 精扫（找高精度 ROI 平衡点的标准做法）**：
- 全区间直接上 0.0001 步进会超计算量上限（1 万点）——**别上来就精扫**。
- **第一轮（粗扫）**：大区间 + 粗步进，快速锁定 ROI 所在区间。例：`开始 1、步进 0.1、结束 10` → 91 点，秒出，先看利润曲线过零点在哪（保本 ROI ≈ 2.x）。
- **第二轮（精扫）**：把区间**收窄到粗扫找到的点附近**（如 2.0~2.5），步进放小到 0.001 甚至 0.0001 → `(2.5−2)/0.001 + 1 = 501` 点，计算量小，能读到**精确到小数点后 3~4 位的 ROI 平衡点**。
- 精扫可多轮递进：2.0~2.5（步进 0.01）→ 2.20~2.30（步进 0.001）→ 2.230~2.240（步进 0.0001），每轮收窄区间 + 加密步进，代价都在几十~几百点。
- 脚本配合：`--roi-start 2 --roi-end 2.5 --roi-step 0.001` 直接传参；精扫后在利润曲线找"最后一个亏损点~第一个盈利点"的区间，即高精度保本 ROI（读法见 §1.4 三步法）。

`#refreshReport()` 流程（`planReportRoiGraph.js:188-380`）：

1. 读输入框，**校验**（开始/步长/结束必须正数，结束 > 开始，否则回填为 开始+步长）。
2. 按步长扫描 ROI，**每个 ROI 用 `SimulationCore.runSimulation()` 重算一份报告**（data[i]，数组）。
3. 算"利润增长金额 / 利润增长率"：相邻点差除以前点利润（取绝对值）。
4. **`resampleToStep`** 把结果重采样到步长 0.1（保证显示点数稳定，与原始步长解耦）。
5. **markArea 着色带**：找利润增长率的 7 个"档位点"（10% / 6% / 4% / 2% / 1% / 0%）对应的 ROI 索引，把 ROI 区间分为若干段色带，标识"成长质量"（**档位按增长率划分：增长率越高 = 该段 ROI 的利润还在快速增长期**）：
   - 严重(+10%) 红色 rgba(255,0,0,0.3) — 增长率最高段（最低 ROI 端）
   - 不良(+6%) 橙红 rgba(255,69,0,0.3)
   - 待改进(+4%) 橙色 rgba(255,165,0,0.3)
   - 一般(+2%) 黄色 rgba(255,215,0,0.3)
   - 良好(+1%) 浅绿 rgba(173,255,47,0.3)
   - 优秀(+0%) 深绿 rgba(50,205,50,0.3) — 利润增长已趋平
   - 卓越(+0) 深绿 rgba(0,128,0,0.3) 收尾（实际数据一般不会触发，代码保留）

> ⚠️ **色带固定按 0.1 步进计算，不随精度变化（源码级机制）**：站点会把任何步进（0.0001~1）的数据**统一重采样到 0.1 步进**，色带档位是在**重采样后的 0.1 步进数据**上找的（见 `planReportRoiGraph.js`）。**所以提高步进精度不会导致色块划分混乱——色带逻辑永远是 0.1 步进的**。原因：若直接按高精度步进算，相邻点利润差变小 → 增长率整体降低 → 达不到 10%/6% 等档位 → 区间没法划分。**结论：改步进只影响你看到的点数/精度，不影响色带分段**；要看色带对应的 ROI 区间，按 0.1 步进理解即可。

### 1.4 怎么读

> **读 ROI 图前须知（口径，务必先对）**：本图 x 轴的 ROI = **GMV ÷ 推广成本**（工具算法，**输入参数**），**不是电商平台的 ROI**——勿直接对比平台数据；读图/向用户解释时应引导关注**推广回报率**（利润÷广告费）曲线。详见 `references/qa.md`。

**坐标轴（双 y 轴，源码 `yAxisIndex` 确认）**
- **x 轴 = ROI**（推广投入产出比）：每 1 元广告费能带回来的销售额，越高 = 广告越划算。
- **左 y 轴（index 0，纯元级 ✅）**：利润 / 广告:XX。
- **右 y 轴（index 1，混单位 ⚠）**：利润率 / 资本回报率 / 推广回报率（%级）+ 利润增长金额（元级）/ 利润增长率（%级）。
- **⚠ 右轴仍有量程压制残留**：利润增长金额（元级，几百~几万）与各率（0.x）同挂右轴时，**增长金额会把率压成直线**——增长金额放右轴是为了**和左轴利润同屏搭配看**（视觉友好），但**同时看增长金额+率时，率仍会被压制**。读 % 级曲线（利润率/资本回报率/推广回报率）建议单独显示（`--show-series`）。

**保本 ROI 怎么找（三步，由粗到精）**
1. **秒判（看尖峰）**：右轴**利润增长率**曲线最高点（尖峰）附近 ≈ 保本 ROI。原理：增长率 = 相邻利润差 ÷ 前点利润（取绝对值），利润接近 0 时分母趋近 0 → 增长率炸出尖峰，尖峰 x 坐标即保本点附近。**注意别混「利润增长金额」**：它是相邻点差（绝对值），在低 ROI 段最大、随 ROI 升高边际递减（曲线陡→平），不是尖峰——两条曲线形状不同。
2. **确认（看过零点）**：左轴利润曲线从负转正的区间，即保本 ROI 所在区间。
3. **精确（粗扫+精扫）**：要精确值，按 §1.3 粗扫+精扫逼近。

> ⚠️ **保本 ROI 是"逼近值"，不是精确点**：ROI 按步进**离散扫描**，利润恰好 = 0 的那个 ROI 几乎不会正好落在扫描点上——通常只能判断"保本 ROI 落在最后一个亏损点 ~ 第一个盈利点之间"，或靠不断加密步进（粗扫+精扫）无限逼近。**所以"保本 ROI ≈ 2.2"表达的是区间/近似，不是精确到小数点的死数**；需要多精确，取决于你扫到多细。

**色带（成长质量评级）**：色带档位按**利润增长率**划分（严重+10% / 不良+6% / 待改进+4% / 一般+2% / 良好+1% / 优秀+0%，见 §1.3 流程第 5 步）。
- **增长率越高（红/橙区）= 当前 ROI 段的利润还在快速增长期 = 逻辑上"不健康"**——不等于真的亏损不健康，而是表示**"如果能提高 ROI 还是尽量提高"**：理论上这个 ROI 段还有明显的提升收益，提 ROI 对利润有好处。
- **增长率越低（绿区）= 利润增长已趋平**——ROI 已吃到该吃的收益，再提 ROI 边际收益很小。
- **读法**：当前参数 ROI 落在哪个色带 → 红/橙区提示"该考虑提 ROI"，绿区提示"ROI 已接近利润上限，别盲目追高"（追高反噬见 §1.5.1 动作 3）。

### 1.5 怎么分析（示例：拼多多推广 139.9/1000单/退款8%，91 点 ROI 1~10）

> 图例来源：`planReportRoiGraph.js` series 定义。**默认只显示「利润 + 利润增长率」两条**，其余要点图例切换（或脚本 `--show-series`）。

> ⚠️ **双 y 轴（源码 `yAxisIndex` 确认）**：左轴 = 利润 / 广告:XX（**纯元级**）；右轴 = 利润率 / 资本回报率 / 推广回报率 / 利润增长金额 / 利润增长率。**左轴已无混单位问题**；**右轴残留量程压制**——利润增长金额（元级）与各率（%级）同轴，同看时增长金额会把率压成直线（增长金额放右轴是为了和左轴利润同屏搭配看，见源码注释）。**读 % 级曲线（利润率/资本回报率/推广回报率）建议 `--show-series` 单独显示**；读数据按 `series[i].data` 取原始值（不受显示影响），**必须区分单位（元 vs %）**。

**一般看的组合**：
- **必看（默认就显示的）**：利润 + 利润增长率 —— 利润看赚亏/保本区间，增长率看尖峰快速定位保本 ROI。
- **常看**：广告:XX（成本随 ROI 怎么降）、推广回报率（推广值不值——工具侧重的最终盈利指标）。
- **按需**：利润率 / 资本回报率（看盈利质量/资本效率）、利润增长金额（看边际收益在哪开始递减）。
- **读图口诀**：先尖峰（增长率）定保本 → 利润线确认区间 → 广告线看成本 → 推广回报率判断值不值。

> 🥚 **彩蛋：同屏看「利润」vs「广告:XX」，判断是不是给平台打工** —— 同时打开这两条线（都是左 y 轴、单位元），在每个 ROI 点对比两条线的高度：**利润 ≥ 广告费 = 你赚的不比平台少（你吃肉）**；**利润 < 广告费 = 你赚的钱大头给了平台（给平台打工）**。例：ROI 3 时若利润 5,000 但广告费 20,000 → 你赚 5 千、平台赚 2 万，等于白忙活；ROI 5 时利润 4.5 万、广告费 1 万 → 反超，才值得放量。**用这个视角找"自己赚 ≥ 平台赚"的最低 ROI，作为投放的"打工分界线"。**

#### 1.5.1 示例分析（拼多多推广 139.9/1000单/退款8%，91 点 ROI 1~10）

**结论（这张图说了什么）**
- **保本 ROI ≈ 2.2**（0.1 步进下，利润最后一个亏损点~第一个盈利点之间，见 §1.4 逼近值说明）：ROI < 2.2 全亏，> 2.2 开始盈利。
- 利润曲线随 ROI 单调上升：ROI 1 → −6.8 万，ROI 10 → +4.6 万，**峰值在 ROI ≥5 后趋平（约 +4.5 万）**。
- 色带分布：ROI 1~2 严重红区、2~3 严重+不良、3~3.4 一般、3.4~4.4 良好、4.4+ 优秀。
- 当前参数 ROI 4 落在"良好"浅绿区（资本回报率 46%、推广回报率 156%）。

**洞察（为什么）**
- 广告费 = 销售额/ROI：ROI 每提 0.1，广告费占比降 1.2 个百分点左右 → 利润近似线性改善，但**到高 ROI 段（≥5）边际收益递减**（广告费占比已很低，再省也有限）。
- ROI 2.2 保本 = 广告费占销售额 ≈ 45% 是"死线"；超过这条线货成本+其他支出必然吃光毛利。
- "成长质量色带"本质是按利润增长率（相邻 ROI 点利润涨幅）切档：**低 ROI 段增长率高（红/橙）= 利润还在快速增长期，理论上提 ROI 还有明显好处**；绿区（增长趋平）= ROI 已吃到该吃的，再提收益已小。
- **边际收益递减的读数证据（看右轴两条线）**：随 ROI 升高，「利润增长金额」「利润增长率」两条曲线整体下行——ROI 每提高 1 个单位带来的利润增量越来越小（利润增长金额从低 ROI 段的大额逐点缩水；利润增长率也一路走低）。这就是"别盲目追高 ROI"在图上的直接证据。

**动作 / 建议**
1. **投放目标定 ROI 4~4.5**：4 已进良好区，4.4+ 才进优秀但增量小 → ROI 4 是性价比拐点，别盲目追高（ROI 5+ 只多几千块利润）。
2. **ROI 2.2 是运营红线**：投放周报盯这个数，ROI < 2.5 就要预警（留 0.3 安全垫），< 2.2 立即停投排查。
3. **⚠ 不要盲目提高 ROI**：理论上 ROI 越高越好，但**ROI 目标设得越高，实际成交量通常会越低**（要求更高的投入产出比 = 更苛刻的流量筛选，能承接的订单量缩水）→ **利润可能反而变少**。叠加边际效应（见上图证据），ROI 越高每提 1 个单位带来的利润增长越低。**评估"ROI 追高 vs 掉量"时，用 §6 ROI×单量双参数热力图**（`roivolume`）一次看全组合：x=ROI、y=单量、色块=利润，直接找"总利润最高"的（ROI, 单量）组合——比在本图逐点改单量（`--volume`）对比高效得多。
4. 想验证不同售价下的 ROI 曲线，用 `--sale-price 159` 临时改价对比（不落库）。

### 1.6 关键坑

1. **页面打开后不会自动改范围**：默认 ROI 1~10 步长 0.1；要扫不同范围（如 0.5~3）必须手动改输入框 + 点"重新生成"。脚本可以代为 fill + click。
2. **不依赖广告就看不到**：脚本 read 前先 `plan_params_ops raw <方案>` 查 `advertising.name`，空就跳过并提示。
3. **双 y 轴容易看错量级（源码 yAxisIndex 确认）**：左轴=利润/广告（纯元级）；右轴=利润率/资本回报率/推广回报率/利润增长金额/利润增长率。**左轴无混单位问题；右轴残留量程压制**——利润增长金额（元级）与各率同轴时会把率压成直线。**读 % 级曲线（利润率/资本回报率/推广回报率）建议 `--show-series` 单独显示；脚本输出摘要必须标清单位（元 vs %）**。

### 2.3 真实行为 / 怎么算

- **固定 ROI（可临时改）、固定单量（可临时改），扫描售价**：开始=0、结束=初始售价×2、步进自动。
- **步进自动归一为 1/2/5×10ⁿ**（0.1/0.2/0.5/1/2/5/10…）：`saleStep = 范围/1000` 后取最近的 1/2/5×10ⁿ，保证点数 ≤1000（源码注释：避免 X 轴标签难看）。**售价步进是 1 位小数的 1/2/5 制**（用户手填任意值也行，但推荐 0.5/1/2/5 这类）。
- 计算逻辑同 ROI 图：每个售价点 `SimulationCore.runSimulation()` 重算，利润增长率=相邻点差/前点利润（绝对值），`resampleToStep` 重采样 0.1。

### 2.4 怎么读

- x=售价、y 左=利润/回报率、y 右=增长率；**找利润=0 的售价 = 保本售价**。
- 曲线一般单调上升（ROI 固定时提价增收）：售价越低越亏（甚至售价 0 附近利润率 -133 倍夸张值），售价越高利润越大。
- **用途：快速看"不同售价下的盈利性"**——不落库临时改售价（--sale-price 是 ROI 图用的；本图用 --roi/--start/--end/--step），对比保本售价与当前售价的差距 = 安全边际。

**⚠ 售价的边际效应（与 ROI 完全不同，2026-08-23 实测验证）**：
- 图例与 ROI 图一样（7 条：利润/利润率/资本回报率/推广回报率/利润增长率/利润增长金额 + 广告:XX），**但没有色带**（无 markArea，别期待色带）。
- **利润增长金额 ≈ 固定**：商品成本不随售价变，提价几乎全部变成利润增量（只被销项税/广告费分走一部分）——所以售价每提高固定步长，**利润增长金额基本不变**（有 1 元以内波动是计算四舍五入，可忽略）。
- **利润增长率持续下降**（过利润 0 点后）：总利润越涨越高（分母变大），增长金额却固定（分子不变）→ 增长率一路走低。**看增长率会得出"越提价越不划算"的错觉——但这里增长率低 ≠ 提价没好处，因为利润增量是实打实的固定值**。
- **所以"要不要提价"是权衡决策（仁者见仁智者见智）**：提价 → 总利润涨（固定增量）但销量通常会降（售价越高能卖出的量越少）——利润增量 vs 掉量风险要一起看（用 §6 ROI×单量、§5 售价×ROI 热力图看组合）。AI 给定价/调优建议时**别只看增长率下"没空间"的结论**，要同时给"提价的固定利润增量"和"掉量风险"两面。
- **实测数据（2026-08-23，售价 100→200 步进 5，ROI 4/单量 1000）**：每步利润差 2930.28/2930.29/2930.38/2930.19/2930.35…（恒定 ±0.19，即四舍五入）；增长率 0.7674→0.4342→0.3027→…→0.0493（单调下降，因利润 3818→62425 分母 16 倍而分子固定）。增长金额恒为 ~2930 而非 5000 全增量：被销项税+广告费（=GMV/ROI 随售价涨）按固定比例分走，每单净增 ~2.93 元。

### 2.5 怎么分析（示例：拼多多推广 ROI=4/1000单，559 点售价 0.5~279.5）

**结论（这张图说了什么）**
- **保本售价 = 93.5 元**（利润 9.27）——当前售价 139.9 远超保本点，**ROI 4 假设下有约 46 元降价空间**。

**洞察（为什么）**

3. 想快速看提价空间：`--sale-price 159/179` 临时对比利润与保本变化（售价图固定 ROI 4，改价用本图参数）。

│   单量步进    #volume-graph-step         默认 100（调整过：减少节点）

### 4.3 真实行为 / 怎么算

- 修改后的默认参数（实测）：售价范围 `initialSale*0.5 ~ initialSale*1.5`、单量 `±500 步长 100`。相比原先的"售价 0~×2、单量大范围步长 10"，**默认从可能上万节点降到 ~300**，代价是首次打开范围较窄。
- 调整参数按需**主动调大范围**重新计算（如 `--sale-start 0 --sale-end 300 --vol-start 0 --vol-end 3000`）；脚本就是干这事的。
- 步进：售价同售价图（1/2/5×10ⁿ 归一）、单量同单量图（最小 1，默认 100）。
- 数据是 `[[x, y, profit]...]` 矩阵。
- **利润范围过滤（常用操作，不是缩放）**：`min-profit` / `max-profit` + 「显示选择的利润范围」按钮（`#saleAndVolume-graph-show-selected-btn`）——**把不在该利润区间的格子变成没有颜色**，**不重新计算、不放大/缩小可视化区域**（改动瞬间生效）。改售价/单量范围才需要点「重新生成分析图」。
- 脚本配合：只传 `--min-profit/--max-profit` 时自动点「显示选择的利润范围」（不重算、快速）；同时传了售价/单量参数则走重新生成。

### 4.4 怎么读

- **色块颜色**=利润高低（visualMap 左下色阶）；**位置**=（售价, 单量）组合。
- **核心读法**：找"最大利润点"（色最暖/最深红）和"保本边界"（色块从蓝/紫过渡到红的等高线，即利润=0 的轨迹）；**盈利区域占比** 量化"多大范围能盈利"。
- **过滤操作**：用 `min-profit/max-profit` + 「显示选择的利润范围」只看目标利润区间的格子（如只看 3万~6万 利润的组合），范围外格子无色。它**不是区域缩放**，不能放大缩小可视化坐标区。

### 4.5 怎么分析（示例：拼多多推广 ROI=4，售价×单量）

**结论（这张图说了什么）**
- 默认范围（售价 70~205 × 单量 500~1500，308 点）：盈利 **82.1%**；最大 +98,131（右上角）、最小 −20,547（左下角）。

**洞察（为什么）**
- 利润 ≈ 单量 × 单均利润，单均利润是售价的函数 → **利润等高线近似双曲线**（售价×单量≈常数），图上表现为"同利润的格子连成一条斜线"。

1. **规划定价×放量的联合方案**：如"促销 99.9 元 + 冲 1200 单" = 约 +3 万利润（格子上可读）；"正价 139.9 + 800 单" ≈ +1.5 万——用图直接对比两个打法的利润区间。

3. 用 `--min-profit 20000 --max-profit 60000` 只看"目标利润带"的格子，快速锁定哪些（售价,单量）组合能到目标利润（不重算，秒出）。

### 4.6 坑

1. **首次打开范围可能不够**（为减少节点改了默认），需要**主动调参**重新计算——这是本脚本最常见的用途。

### 7.0 热力图的"目标利润甜点"用法（AI 调优必知）

> 三个热力图**没有图例**（色块颜色本身就是图例：颜色=利润高低），不用找图例。

**场景**：用户想要赚到**固定的利润目标**（如"希望利润金额到 20000 左右"）——用三个热力图寻找所有能达成目标的"甜点"（参数组合区间）：

- **方法**：配合 `--min-profit/--max-profit` 利润过滤（点「显示选择的利润范围」，不重算）**只看目标利润区间的格子**——比如 `--min-profit 18000 --max-profit 22000`，热力图会把利润不在 1.8万~2.2万 的格子全部变无色，剩下有色的格子 = 所有能达到"2 万左右"的 (参数1, 参数2) 组合。
- **三个热力图各看一个维度组合**：
  - **售价×单量**（§4）：定价多少 + 卖多少单能到 2 万 → 找"价格-量"甜点（如 120 元 × 1300 单 或 140 元 × 1000 单）
  - **售价×ROI**（§5）：定价多少 + 投放效率多高能到 2 万 → 找"价格-效率"甜点
  - **ROI×单量**（§6）：投放效率 + 卖多少单能到 2 万 → 找"效率-量"甜点
- **AI 应用**：用户提"想赚 X 万"时，**主动用目标利润过滤**，把"能达到目标的甜点区间"圈给用户，而不是只报单点利润；甜点通常是一整片区域（组合空间），给出"区间范围 + 推荐点"比单一答案更有用。
- **举例**：`--roi-start 3 --roi-end 6 --vol-start 800 --vol-end 1500 --min-profit 18000 --max-profit 22000` → 输出 ROI×单量组合中利润 1.8万~2.2万 的格子分布，即"ROI 3~6、单量 800~1500 下达成 2 万利润的所有甜点"。
- **⚠ 区间设窄会"切出空洞"（2026-08-23）**：目标区间（min~max）很窄时，显示出来的可选组合会**不连续**（中间很多组合的利润超出区间被过滤掉），**不代表那些组合真的不能选**。例：售价 208/ROI 3 → 利润 30,469；售价 203/ROI 3.1 → 利润 34,393——若设目标 30000~32000，34,393 那个组合就不显示，但它**完全可用**（只是利润高于目标上限）。**所以找甜点时：min 以目标为基准（硬下限），max 适当放宽**（如目标 3 万 → 设 `--min-profit 30000 --max-profit 40000` 甚至更大），先看全量高于目标的组合，再人工挑接近目标的，避免窄区间造成"可选组合稀疏/断档"的误判。
