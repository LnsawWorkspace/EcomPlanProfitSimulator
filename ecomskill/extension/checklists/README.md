# checklists（渠道 · 填参检查清单库）

> 本文件夹用于**辅助填写方案参数**：每个文件 = 一个渠道（或渠道+场景）的支出检查清单，告诉 AI/用户「当方案是 XX 渠道时，可能有哪些支出项目、成本类型、税率与常见金额」。

## 定位

- 每个文件 = 一条逻辑渠道的支出清单，命名 `XX-XX-checklist.md`（中文，如 `拼多多通用checklist.md`、`抖音达人直播checklist.md`）。
- 内容覆盖：每单支出 / 部分订单支出 / 固定支出 三个模块的常见项目 + 成本类型 + 税率 + 订单比例 + 退款/回收率参考 + 满减/优惠券处理规则。
- **填参数前先按方案渠道找对应清单**；没有对应渠道的，复制现有清单按需增删。

## 规则

- 命名规范：`<平台/渠道>-<场景>checklist.md`，简洁中文。
- 一个方案 = 一条逻辑渠道（见 SKILL.md「方案」节）→ 一个清单尽量覆盖该渠道所有常见支出场景。
- 满减 / 优惠券 / 平台补贴 = 售价调整（作为新渠道新方案），**永远不进支出模块**（判断口诀：钱进了谁的口袋——平台/快递/服务商拿走=支出，买家少付=售价调整）。
- **手续费类支出默认归「部分订单支出」**：支付/交易手续费（花呗、信用卡、微信/支付宝支付、分期免息等）**通常不是全部订单都产生**——只有用了对应支付方式/场景的订单才扣。填法：放部分订单支出模块，**订单比例 = 该支付方式/场景的订单占比**（如花呗支付约 30%）。只有确定**每一单都必然产生**的手续费（如平台按全部成交额统一扣的技术服务费）才放每单支出。
- **部分退款（退部分钱给买家）用「部分订单支出」近似模拟**：站点退款率是"整单退款"语义，退 10/20 元这种部分退款模拟不了 → 建一条部分订单支出（num 按金额 或 per 按售价%，订单比例=发生部分退款的订单占比），**只是近似**。税率：退应收的钱 → 跟**销项税率**走（多销项税率随便选一个）；**额外补贴/小额打款 → 税率 0**。实操建议：**部分退款最好用「补贴」方式做，不要和订单退款混在一起**。
